BinDay finds the stuff your machine does not need any more — build output, dependency folders, package caches, temp files, old installers, duplicate files, oversized videos and leftover app packages — and then explains every single one of them: what it is, what would happen if you removed it, and how to get it back. You tick what you want, and it waits for you to say yes.

What it finds

Each item comes with its size, its collection, and a plain sentence explaining what removing it means. If it cannot prove an item is disposable, it stays out of the list.

Build output

node_modules, obj and bin, target, .venv, __pycache__, .dart_tool, .gradle, .next and friends.

Only offered when the project file sits next to it, so a folder that merely looks disposable is left alone.

Package caches

The npm, Yarn, pnpm and pip download caches, plus the NuGet, Gradle and Maven repositories and %TEMP%.

Graded Check when clearing them means the next build needs the network.

Temporary files

Scratch space that applications are supposed to clean up themselves. Files that are in use are skipped instead of failing.

Old installers

.msi, .iso, .exe and friends over 50 MB and more than 30 days old, in Downloads and on the Desktop.

Always graded Review, so they can only ever go to the Recycle Bin.

Big videos, photos and audio

Media files over the size floor you choose, with real Explorer-style thumbnails so you can recognise them at a glance.

These are your own files, so BinDay never calls them junk. They are graded Review and can only go to the Recycle Bin.

Leftover app packages

.apk, .xapk, .aab and friends left lying around after you installed the app somewhere else.

Graded Review, Recycle Bin only.

Redundant installs

Several copies of the same installer in your Downloads folder. The newest one is kept, the older ones are offered.

Any very large file

A single file over 300 MB, whatever it is, listed so you can decide whether it still earns its place.

Duplicate files

Grouped by size, then by a cheap prefix hash, then by a full SHA-256. Only files that agree on all three are duplicates.

The copy with the shortest path is kept; the rest are offered for removal.

And nothing else

No registry tweaks, no background services, no telemetry, no account. The only thing that touches the network is the "Check for updates" command, and only when you press it. No silent "cleanup" while you work.

How it stays safe

The product is not the scanning, it is the trust. Every item carries a grade, and the grade decides what the app is allowed to do.

Safe

Regenerated automatically by your tools. These can be moved to the Recycle Bin or deleted permanently.

Check

Regenerated, but the next build would need the network. Recycle Bin only.

Review

Could be something you want to keep. Recycle Bin only.

  • Nothing is deleted until you tick it and confirm.
  • Permanent delete is refused for anything that is not graded Safe — by the engine, not just by the button.
  • Windows, Program Files, ProgramData, AppData, $Recycle.Bin and drive roots are never walked and never deleted.
  • Symbolic links and junctions are never followed.
  • Every cleanup is written to a local history you can read back in the app.
  • "Check for updates" tells you when a newer version is out and fetches it for you. Nothing else talks to the network.

How it works

1

Pick a folder

Your user profile is pre-filled. Point it at a project folder instead if that is where the junk is.

2

Browse the collections

Dev junk, caches, videos, photos, app packages, redundant installs and more — each with a live count and size. Sort by size, name or date, in big cards or a details table.

3

Read what would happen

Select an item and the panel tells you what it is, exactly what would be removed, and how to get it back if you are wrong.

4

Tick and confirm

Move the ticked items to the Recycle Bin, or delete the safe ones for good. A final review screen lists everything first. Either way, you decide.

Ready when you are

One small file, and you are running. Install it properly if you prefer.

Running it from your Downloads folder is fine — the Desktop shortcut button inside BinDay puts an icon on your Desktop so you can always find it again.
